# 视频与实时摄像头检测

PCB-Component-Inspector 从 v1.1.0 开始支持三种输入方式：

1. 上传静态 PCB 图片；
2. 上传本地视频文件；
3. 浏览器摄像头实时检测。

## 实时摄像头

启动图形界面：

```bash
streamlit run app.py
```

在首页选择“实时摄像头”，然后：

1. 选择模型来源；
2. 建议先使用 640 推理分辨率；
3. CPU 环境建议设置为每 2~3 帧执行一次检测；
4. 实时模式建议默认关闭切片推理；
5. 点击 WebRTC 控件中的 `START`；
6. 浏览器请求摄像头权限时选择允许；
7. 将 PCB 放入摄像头画面，即可持续看到检测框、置信度和当前分类计数。

实时画面中的计数表示“当前帧同时检测到的目标数量”，不是对整个视频时间轴进行累加，因此不会把同一个元器件在连续多帧中重复累加。

## 上传视频

选择“上传视频”后，可上传 MP4、MOV、AVI、MKV、WebM、M4V 等常见格式。

系统会：

- 使用 OpenCV 解码视频；
- 按设置的间隔执行 YOLO 推理；
- 在中间帧沿用最近一次检测框；
- 将检测框、类别、置信度和当前分类计数写入输出视频；
- 生成可下载的 MP4 结果文件。

视频结束后页面显示的表格对应最后一次检测结果；每一帧的实时计数以视频左上角叠加信息为准。

## 每 N 帧检测一次

视频检测比单张图片检测更耗算力。`每 N 帧执行一次检测` 用于降低推理压力：

- `1`：每帧都执行 YOLO，结果最及时，但算力要求最高；
- `2~3`：推荐的通用实时设置；
- `4~5`：适合 CPU 或高分辨率摄像头；
- 更大数值：适合画面变化缓慢、主要观察静态 PCB 的场景。

跳帧并不是丢弃视频帧。系统仍会输出每一帧，只是部分帧不重新执行 YOLO，而是沿用最近一次检测结果。

## 切片推理与实时模式

静态高分辨率 PCB 图片适合开启切片推理，因为小电阻、小电容等目标在整图缩放后可能变得过小。

实时视频中，切片意味着一帧需要执行多次 YOLO，因此会显著降低帧率。建议：

- 日常实时检测：关闭切片；
- 固定机位、画面变化慢、GPU 性能较高：可尝试开启；
- 如果元器件很小，优先让摄像头靠近 PCB 或提高光照，再考虑切片。

## 浏览器与网络要求

本机运行时，使用 Streamlit 默认的 `http://localhost:8501` 即可请求本机摄像头。

如果将应用部署到另一台服务器并通过网络访问，浏览器通常要求页面运行在 HTTPS 安全上下文中才能开放摄像头权限。远程 WebRTC 部署还可能需要配置 STUN/TURN 网络服务。

## 常见问题

### 点击 START 后没有画面

依次检查：

1. 浏览器是否允许当前页面访问摄像头；
2. 摄像头是否被会议软件、相机软件等独占；
3. 浏览器地址栏中的摄像头权限是否被设置为“阻止”；
4. 刷新页面后重新点击 `START`。

### 实时检测很卡

按以下顺序降低负载：

1. 将视频推理分辨率降到 640 或 512；
2. 将检测间隔改为每 2~5 帧一次；
3. 关闭视频切片推理；
4. 关闭其他占用 CPU/GPU 的程序；
5. 有 NVIDIA GPU 时使用正确的 CUDA/PyTorch 环境。

### 实时画面漏检小元器件

可以尝试：

- 调整摄像头，让 PCB 占画面更大比例；
- 增加均匀光照，降低反光；
- 提高推理分辨率；
- 在算力允许时开启切片推理；
- 使用真实相机采集的数据重新标注并微调模型。
