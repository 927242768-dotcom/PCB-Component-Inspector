# FPGA 简历项目表述

## 项目名称

**FPGA + ARM 实时 PCB 元器件视觉检测系统**

## 当前即可证明的技术内容

- 设计 AXI4-Stream 流式图像预处理链路，实现 RGB888 转灰度、3×3 Sobel 边缘提取和可配置阈值化。
- 使用两级行缓存和横向移位寄存器构造 3×3 窗口，梯度幅值采用 `|Gx|+|Gy|` 的硬件近似，避免平方根运算。
- 设计 AXI-Lite 控制寄存器，ARM Linux 通过 UIO/mmap 动态配置 Sobel、阈值使能和阈值参数。
- 构建 ARM + FPGA + YOLO 异构链路：FPGA 负责像素级流处理，ARM 负责视频调度和控制，YOLOv8 完成 21 类 PCB 元器件检测、分类和自动计数。
- 支持图片、视频和摄像头实时检测，并提供 CSV/JSON 检测报告和 GitHub CI/Release 工程流程。

## 面试时的 30 秒讲法

“这个项目不是单纯在 PC 上跑 YOLO。我把实时视频链路拆成 FPGA 和 ARM 两部分：FPGA 用 AXI4-Stream 做 RGB 转灰度、Sobel 和阈值处理，其中 Sobel 用两行缓存构造 3×3 窗口；ARM Linux 通过 UIO 映射 AXI-Lite 寄存器控制 FPGA，再从 VDMA/V4L2 获取处理后的帧交给 YOLO 做元器件分类和计数。这样 FPGA 做确定性的像素吞吐，ARM 做控制和 AI 推理，整个项目体现的是软硬件协同而不是只调用模型。”

## 高频追问

### 为什么不用 FPGA 跑完整 YOLO？

完整 YOLO FPGA 部署需要量化和专用卷积加速架构。当前阶段先把适合 RTL 的像素预处理硬化，保证数据通路、AXI 接口和 ARM 控制都能真实讲清楚；后续再基于目标板资源决定是否做 INT8 卷积加速。

### 为什么 Sobel 用两行缓存？

计算当前 3×3 邻域需要当前行和前两行数据。当前行来自输入流，前两行存入 BRAM，因此两条 line buffer 就能连续构造三行窗口。

### 为什么不用 sqrt(Gx²+Gy²)？

平方和开方会增加硬件资源和流水线复杂度。边缘检测只需要近似梯度强度，因此采用 `|Gx|+|Gy|`，更适合 FPGA 定点实现。
